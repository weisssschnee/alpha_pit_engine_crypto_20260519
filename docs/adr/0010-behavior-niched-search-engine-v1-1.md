# ADR 0010: Behavior-Niched Search Engine V1.1

## Status

Accepted as a one-run development-system exception on 2026-07-27.

## Context

The fresh-state 2,000-candidate system canary established a CEM unit-compute
density increment and verified Evolution repair operators, but Evolution
produced fewer new behavior families per 1,000 evaluations and more behavior
duplicates than typed random. The user explicitly authorized the precise next
step proposed in the conversation: one 3,000-candidate, equal-count,
spent-development system Arena focused on search capability.

## Decision

- Add behavior-family champion plus mechanism/skeleton frontier admission to
  CEM updates.
- Preserve reward-first Evolution tournaments and existing typed operators.
- Bound Evolution population occupancy by behavior family and skeleton.
- Prefer cross-skeleton compatible crossover.
- At each checkpoint, update Evolution operation probabilities from
  policy-local new-family productivity using a frozen Beta prior and a fixed
  minimum probability.
- Run typed random, CEM V2.1, and Evolution V2.1 for 1,000 strict candidates
  each over two continuous checkpoints.

## Boundaries

This decision creates no new AST, compiler, evaluator, scheduler, database,
checkpoint service, data admission, Alpha claim, OOS role, challenge/recent/
May-stress/forward access, promotion, latent priority, relational training, or
future-Arena arm qualification. It does not import prior candidate, reward,
distribution, population, policy, or archive state. The broader
`NEW_PERFORMANCE_SEARCH_FROZEN` boundary remains in force outside this exact
system-only run.
